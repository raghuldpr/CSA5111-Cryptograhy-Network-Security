1.3  Requirement change: (a) 1 recipient, (b) 5 recipients, (c) 10x message
==============================================================================
PREDICTION (written before running):
  size : (b) = (a) + 4 extra slots x (8+2+256) = +1064 B; (c) payload 10x larger but text is repetitive so compresses well
  pk ops: (a)=1 sign+1 wrap=2; (b)=1+5=6; (c)=2.   sym ops: 1 in every case
  sender work grows more with recipient count in public-key ops (expensive, 256 B each);
  with message size only the cheap symmetric/hash work grows.

case                plain B  envelope B  pk ops  sym ops      ms
(a) 1 recipient         300         649       2        1     2.1
(b) 5 recipients        300        1715       6        1     2.6
(c) msg x10            3000         674       2        1     3.2

ACTUAL vs PREDICTED: (b)-(a) = 1066 B (predicted 1064: matches). (c) is only 25 B larger for 2700 B more plaintext (compression).
Interpretation: sender work scales with recipients in the expensive public-key dimension; message size
only affects the cheap symmetric dimension. Hybrid encryption means pk ops == 1 + recipients regardless of size.
